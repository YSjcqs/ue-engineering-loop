# 六阶段状态机与 Gate 模板（WORKFLOW_STATE_MACHINE）

> 本文件是 SKILL.md §2.3 的完整展开：每个阶段的 Output / 风险 / Exit Gate，以及可直接复制的 Plan、Gate、验收模板。
> 核心思想：**上下文压缩或换任务后，恢复的是当前 Gate，而不是一串失去优先级的 Todo。**

---

## 1. 六阶段详解

### M0 · 定位事实

| 项 | 内容 |
|---|---|
| **Output** | 真实调用链、现状基线、复现步骤、**事实/推断分栏**、消费者与 owner 清单 |
| **风险** | 未找准所有权；把缓存/编辑器表象误判为根因；只看第一处可见症状 |
| **Exit Gate** | 根因或目标状态可解释；具备以下之一：稳定失败信号、能失败的红测试、缺失能力证明、可重复的现状基线。新功能不强求先有历史 bug。 |

**执行要点**：
- 先只读建立完整链路（作者数据 → 序列化/保存 → 加载/预加载 → 运行时消费 → 最终读回），列每一层的 owner。
- **写入范围可以窄，只读调查范围往往必须更宽**：代码路径只是 locator 不是 contract；专家脑中的架构图必须显式化进入工作集。
- 把「现象」与「根因」分开：现象只是观察，不提前指定根因所在层。
- 本阶段**只读，不改产品代码**。

### M1 · 冻结合同

| 项 | 内容 |
|---|---|
| **Output** | 目标、非目标、不变量、兼容边界、性能预算、回退策略；写入范围与文件 owner |
| **风险** | 不同会话/Agent/模块同时发明不同的「正确行为」 |
| **Exit Gate** | **Oracle 唯一**；消费者、owner 与状态迁移已列清 |

**合同七要素**（完整模板见 `PROMPT_CONTRACTS.md`）：OUTCOME / ORACLE / SCOPE / NO-GO / CONSTRAINT / ACCEPTANCE / AUTHORITY。

### M2 · 最小实现

| 项 | 内容 |
|---|---|
| **Output** | 只改变一个 seam 的最小可验证切片 + 负向用例 |
| **风险** | 顺手重构、文件范围膨胀、旧行为被静默改写 |
| **Exit Gate** | Diff 小且可解释；失败用例由红转绿；回滚路径存在 |

**切片选择原则**：
- 切片要「能暴露架构风险」：选同时穿过最难合同（多数据源/事务/兼容）的样本，而不是最简单的纯本地字段。
- **纵向贯通**：一条链从发现、编辑、事务、持久化到兼容读回全通，横向能力（批量、美化、性能）明确延期为独立 Gate。
- **正向与失败路径放进同一切片**：不仅证明 Save 成功，也证明失败不留半写入数据。
- 用明确的 **Not Yet** 保持切片锋利——延期项不是遗忘项，留在 Plan 中等授权。

### M3 · 机械验证

| 项 | 内容 |
|---|---|
| **Output** | exact-file gate、编译（Editor+Game）、focused 与 full Automation 证据 |
| **风险** | **旧 DLL、旧进程、旧日志验证了上一版代码** |
| **Exit Gate** | 测试来自**最后一次源码修改之后**，结果与日志可追溯 |

### M4 · 真实验证

| 项 | 内容 |
|---|---|
| **Output** | 可见 Editor、Save/Reopen、Streaming、Cook、DS/Client、性能 |
| **风险** | 白盒内部状态正确，但用户界面仍为空、错选或不可操作 |
| **Exit Gate** | 高价值真实用户链通过；未执行项显式标记 **NOT RUN** |

### M5 · 复用收口

| 项 | 内容 |
|---|---|
| **Output** | 当前权威状态、证据入口、Do Not Repeat、Rule/Skill/Automation 沉淀 |
| **风险** | 历史快照与当前结论冲突；下一会话重复已关闭工作 |
| **Exit Gate** | 任何接手者都能在 **10 分钟内**找到下一最小动作 |

**沉淀载体判断**（详表见 `SKILL_DISTILLATION.md`）：始终生效的不变量 → Rule；机器可判定的约束 → Automation；稳定结构 → Template；同类任务的高成本判断 → Skill；只在当前任务有效 → Handoff/STATUS。

## 2. 状态词表（只用这五种）

```
Done / In progress / Next / Blocked / Deferred
```

- **Blocked** 是健康状态：环境缺入口、二进制过期、需要写生产资产时，正确结果可能是 BLOCKED——它保护证据含义，明确告诉下一步是修环境、补可测性或取得授权。**禁止**绕过产品入口调内部 API「制造通过」。
- **Deferred ≠ 遗忘**：延期项留在 Plan，等基础合同稳定后逐个获得授权。

## 3. Plan / Gate 模板（可直接复制）

### 3.1 阶段卡

```markdown
## 阶段 / Gate：
**当前基线**：
**Entry 条件**：
**本阶段动作**：
**明确非目标**：
**Exit 条件**：
**证据等级**：(T0/T1/T2/T3/T4，见 QA_EVIDENCE_LADDER.md)
**回退路径**：
**依赖与风险**：

状态只使用：Done / In progress / Next / Blocked / Deferred
```

### 3.2 GO / NO-GO 验收模板

```markdown
## 本阶段只有全部满足才允许 Go：
- [ ] 目标行为可复现（附复现步骤）
- [ ] 失败路径有明确结果（负向用例）
- [ ] focused Automation 全绿（附输出，Executed>0）
- [ ] 可见 QA 覆盖真实用户链（截图/读回证据）
- [ ] 无意外文件/资产污染
- [ ] 架构与性能硬门槛通过
- [ ] 报告、日志、截图来自**同一最终源码**
- [ ] 已写明仍未完成和禁止宣称的能力（NOT RUN 清单）

否则 No-Go：保留证据，修复后重走当前 Gate，不扩大范围。
```

### 3.3 Current Truth Packet（长任务外部记忆，跨天/换会话前必写）

```markdown
## 当前唯一目标
（一句话，用户可观察的最终结果）

## 绝不能破坏（不变量）
- ...

## 当前源码仍然有效的证据
✓ （哪层 Gate 通过 + 对应哪个版本的源码/产物）

## 已明确失效
× （晚于哪些修改的旧绿灯）

## 尚未证明
○ （NOT RUN 清单）

## 唯一下一步
（最小、确定、可执行的下一动作）

## 禁止重复（Do Not Repeat）
- （已否定方案 + 为什么）
```

> **压缩最危险的损失是「否定」**：「未验证」「禁止写 X」「旧结论已废止」「高层证据仍缺失」一旦被压掉，剩下的肯定句会制造虚假的完成感。

---

## 4. 两条裁决原则

1. **Go 只表示允许进入下一阶段，不表示已经生产可用。**
2. **高层失败不能用更多低层绿灯抵消**：一个功能「界面能打开」不能证明数据所有权、保存、兼容和运行时已经成立。任何一层失败只回到自己的 owning seam，并使更高层旧证据失效。

---

## 5. 风险前置（POC 裁决点）

把最高风险的技术假设做成 **POC 阶段**，放在依赖它的大规模开发之前：

- POC 阶段需写明：失败即架构阻断 + 降级方案。
- 例如「USTRUCT 多态在序列化/扩容/跨资产粘贴后是否可靠」→ 用最小 Spec 实测裁决（实测案例：结论为可行，需 `FObjectWriter/Reader`，见 `UE_RUNTIME_GOTCHAS.md` §2、§4）。
- POC 通过后，后续所有阶段无需再担心该架构问题——**一次裁决，全项目受益**。
